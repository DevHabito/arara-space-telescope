# P0.8 — keyed packet custody and source-authenticity boundary

**Precommitted:** 3 November 2026, before creating the P0.8 implementation or executing its acceptance tests. This is an engineering audit using unlabelled, deterministic numerical frames; it is not a real observatory data run, detector calibration or scientific holdout.

## Question and trust assumptions

P0.7 chained SHA-256 checksums over caller-declared metadata and numeric frames. Anyone who controls both the records and the hash can forge a self-consistent transcript. I want a separate verification boundary in which an externally provisioned *symmetric secret key* must be possessed to produce a valid keyed message authentication code (MAC). This changes the assumed adversary, but it does **not** prove that a telescope generated the measurements.

The construction uses the standard-library `hmac`/SHA-256 implementation with `hmac.compare_digest`, not a custom cryptographic primitive. The independently verified prior descriptions are **Hugo Krawczyk, Mihir Bellare and Ran Canetti (February 1997), RFC 2104, _HMAC: Keyed-Hashing for Message Authentication_, DOI 10.17487/RFC2104** (https://www.rfc-editor.org/info/rfc2104/) and **Magnus Nystrom (December 2005), RFC 4231, _Identifiers and Test Vectors for HMAC-SHA-224, HMAC-SHA-256, HMAC-SHA-384, and HMAC-SHA-512_** (https://www.rfc-editor.org/info/rfc4231/). This prior art is not an ARARA invention or validation of a physical instrument.

The trusted verifier is configured in memory with a fixed externally supplied key ID and secret of at least 32 bytes, plus a pinned session/instrument/target/clock ID and frame dimensions. **No production key, trust root, certificate, sensor credential, or independent key-provisioning mechanism exists in this repository.** Committed keys, if any, may appear **only as plainly labeled public test fixtures** and cannot be claimed to secure a real producer. The verifier and an example test signer are in the same experimental Python process; this is not an independent source attestation test.

## Frozen proposed boundary

1. Create `AuthenticatedPacket`, an immutable dataclass containing index, pinned labels, frame shape, exact producer-supplied raw bytes, declared P0.7 start/end times and uncertainties, previous MAC (lowercase hex) and current MAC (lowercase hex). The wire payload is defined as little-endian, C-order IEEE binary64 samples of shape `(curves, stars)`. These bytes are **not** raw camera ADC or FITS products; they are a fixed numerical encoding produced by the test fixture.
2. The MAC input is a versioned binary domain separator followed by a four-byte big-endian metadata-length, canonical UTF-8 JSON metadata (sorted keys, explicit schema version and previous MAC), a four-byte big-endian frame-byte-length, then the **unchanged exact frame bytes**. Reject invalid metadata encodings, wrong lengths or malformed types without constructing a score. Include the session, key ID, instrument ID, target ID, clock ID, cadence, shape, time values, uncertainties and previous MAC in the canonical signed message.
3. The first packet's previous MAC must be 64 lowercase zero hex digits. Each subsequent packet must present the previous **verified** packet's MAC. The receiver checks the next index, expected labels/key ID, chained predecessor and MAC **before interpreting the float64 frame**, then passes the decoded frame and declared exposure metadata to the unchanged P0.7 `ExposureProvenanceLedger`. Wrong credentials, invalid shape, missing indices, or any failed check **permanently block the receiver**; the rejected packet is not committed.
4. The receiver retains copies of immutable `AuthenticatedPacket` objects (including original frame bytes). It exposes these copies as a tuple for inspection and never rewrites them into allegedly original sensor files. Scoring always verifies the P0.7 chain and uses the currently accepted last prefix. The MAC key is not included in the public packet or audit report. No network or disk persistence is introduced.

## Predeclared acceptance tests

- A deterministic finite unlabelled `(2,9,180)` array, NumPy seed `20261103`, with the same purely mathematical positive ramp used in earlier numerical audits. Valid packet data use start `1000+2k`, end `1000.5+2k`, each uncertainty `0.01`, and consecutive indices. The test-only key is a fixed **public fixture**, not a production secret. At cadences **81, 83 and 179**, every score/diagnostic field must match `score_observed_prefix(stars[:, :, :k+1], endpoint=k)` **bitwise**.
- RFC 4231 test case 1 checks the standard library HMAC-SHA-256 independent known-answer vector: key `0b` repeated 20 times, data `Hi There`, expected digest `b0344c61d8db38535ca8afceaf0bf12b881dc200c9833da726e9376c2e32cff7`. This only checks the primitive's stated known answer, not our complete framing.
- A changed frame byte, declared timestamp, target label, clock label, key ID, MAC, prior-MAC, wrong verifying key, wrong shape and truncated payload must all be rejected, permanently block a fresh receiver and commit no rejected packet.
- Duplicate, skipped or reordered cadences are rejected. A packet stolen from the middle of a valid sequence cannot be appended to a different prefix. Resending a previously accepted packet must block the active receiver.
- Mutation of the caller's original NumPy array or a separately exported P0.7 snapshot after packet construction cannot alter stored signed bytes. Identical packet streams yield identical HMACs with the same **test** key.
- A source with **the correct shared key** can construct an arbitrary different self-consistent transcript: its MAC must verify when session/indices/declared bounds match. Likewise, replaying a complete previously valid transcript into a **fresh receiver** configured with the same key/session is accepted. These negative threat-model controls must be recorded as **limitations**, not hidden, and show why HMAC possession is not observatory authentication or durable replay protection.
- Invalid key length/type, empty trust identifiers, unsupported shape, NaN/nonfinite frame, and malformed raw bytes are rejected. No statistical threshold, FPR, power study, astrophysical simulation truth, signed certificate or real instrument data.
- Any failed test is preserved and rerun after a clearly identified correction without retroactive tolerance changes. Verify the **exact final head** by reading the cloud Python audit, Lean 4, all historical regression suites, six workflow outcomes and historical manifest hashes. No alteration of `milestones/`, root `README.md` or `docs/SCIENTIFIC_STATUS.md`.

## Claims this protocol explicitly forbids

HMAC with a separately provisioned secret can check that the party constructing a packet *had that secret*, assuming it was properly generated, held confidential and used correctly. It cannot establish that the signer was an astronomical instrument, that a clock was calibrated, that a target was correctly identified, that detector noise was physically measured, or that a forged but correctly keyed packet is truthful. The test key is public by design. There is no external root of trust, secure boot, device attestation, key revocation, independent signature, append-only archive, authenticated timestamping service or persistent replay database. The P0.7 absolute time uncertainty remains a **producer assertion**, not a measured uncertainty budget. This is a **signed-message custody exercise**, not production authentication.
